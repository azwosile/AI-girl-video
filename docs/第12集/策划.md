## 5. 事实核对（docs.github.com，2026-10）

- 保护分支：公开仓库在 GitHub Free 上可用，私有仓库需要 Pro / Team / Enterprise。规则可以写分支名或通配符。**默认禁止强制推送和删除分支**；默认管理员可以绕过，勾选 “Do not allow bypassing the above settings” 后管理员也受约束。被拦时报 `remote: error: GH006: Protected branch update failed for refs/heads/main.`
- 规则选项：Require a pull request before merging（N 个批准、Dismiss stale pull request approvals when new commits are pushed、Require review from Code Owners、Require approval of the most recent reviewable push）；Require status checks to pass（Require branches to be up to date）；Require conversation resolution；Require signed commits；Require linear history；merge queue；Lock branch；限制谁能推送。
- CODEOWNERS 可以放在 `.github/`、仓库根目录或 `docs/`；每行“路径模式 + 负责人”，后面的规则优先；PR 改到对应文件会自动请求负责人审查。
- 合并方式：Create a merge commit / Squash and merge / Rebase and merge，可以在仓库设置里只允许其中几种；“Automatically delete head branches” 让合并后自动删除分支。
- Release 基于 Git 标签；更新说明可以手写或自动生成；GitHub 自动附源码 zip / tar.gz；单个文件小于 2 GiB，最多 1000 个附件；需要写权限才能管理 Release。工作流用 `on: push: tags: ['v*']` 触发，`gh release create "$GITHUB_REF_NAME" --generate-notes 文件` 建 Release（`GH_TOKEN: ${{ github.token }}`，`permissions: contents: write`）。
- 标签默认不随 `git push` 推送，要 `git push origin v2.0.0` 或 `git push --tags`；`git tag -a` 是附注标签。版本号按语义化版本 MAJOR.MINOR.PATCH。
- GitHub flow：开分支（名字简短）→ 提交并推送 → 开 PR（可以先开草稿，用关键字关联 Issue）→ 审查 → 合并 → 删分支。
