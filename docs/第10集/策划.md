## 5. 事实核对（docs.github.com，2026-10）

- 没有写权限的仓库不能直接推送；Fork 会在自己名下创建一份复刻，可以自由推送。
- 复刻 clone 下来后 `origin` 指向自己的复刻；用 `git remote add upstream <原项目地址>` 添加上游。
- 同步复刻：复刻页面文件列表上方的 **Sync fork** 下拉 → **Update branch**（有冲突时会提示创建 PR 解决）；命令行为 `git fetch upstream` → `git checkout main` → `git merge upstream/main`，然后推送到自己的复刻。
- 推送后复刻页面会出现 **Compare & pull request**；也可以用 **Contribute → Open pull request**。PR 的 base 是原项目分支，head 是复刻里的分支。
- 在 PR 描述里写 `Closes #42`（或 fixes / resolves 等关键字），PR 合并进**默认分支**时会自动关闭该 issue；目标不是默认分支时关键字不生效。
- 从复刻发起的 PR 可勾选 **Allow edits by maintainers**，让有权限的维护者直接向 PR 的分支推送修改。
- PR 打开后，继续向同一个分支推送提交，PR 会自动更新；审查评论可以 Resolve conversation，修改后可重新请求审查（Re-request review）。
- 仓库首页 README 旁的标签页会显示 Code of conduct、Contributing、License、Security 等文件；`good first issue`、`help wanted` 是 GitHub 默认标签。
- 没有许可证的代码默认保留全部版权，他人不能随意复制、分发或修改；MIT 许可允许使用、复制、修改、合并、发布、分发、再许可和销售，条件是保留版权声明和许可声明。
