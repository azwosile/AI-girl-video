## 4. 配音要点

- 命令里的英文照读，参数改成中文说法：`-S` 读成“搜代码参数”，`-L` 读成“行号参数”，`-w` 读成“忽略空白的参数”，`-x` 读成“x 参数”，`revert` 前面带“撤销提交命令”，`cherry-pick` 前面带“摘樱桃命令”。
- “行”容易读成 xíng，朗读稿里写成“航”（字幕仍是“行”）。
- “P R”分开写，避免连读。
- Gemini 台词开头带“喵？”，结尾“清白了喵！”的“喵”容易被吞，审核时重点听。
- 豆包用自己的 GPT-SoVITS 模型（`tts_doubao.py`，参考音频 r19）；注意它偶尔会冒出“为你提供帮助”之类的幻觉。

## 5. 事实核对（git-scm.com / docs.github.com，2026-10）

- `git log -- <path>` 只列出改动过该路径的提交。
- `git log -S<string>`（pickaxe）找出让该字符串**出现次数**变化的提交，只是移动位置不算；`-G<regex>` 则匹配 diff 里增删的行。
- `--grep` 搜提交说明，`--author` 按作者，`--since` / `--until` 按时间；多个条件可以组合使用。
- GitHub 文件页右上角有 History（该文件的提交记录）和 Blame 按钮；Blame 视图每段旁有“查看这次改动之前的 blame”图标，可逐层往前查。
- `git blame <file>` 每行显示最后改动它的提交、作者和时间；`-L 40,50` 只看指定行；`-w` 忽略空白改动（还可以用 `--ignore-rev` / `.git-blame-ignore-revs` 跳过格式化提交）。
- `git bisect start` → `git bisect bad`（当前）→ `git bisect good <rev>`；每步把范围减半，n 个提交最多约 ⌈log₂n⌉ 步（100 个 → 7 步）；`git bisect skip` 跳过无法测试的提交；`git bisect reset` 回到开始前的分支；`git bisect run <cmd>` 按退出码自动判定（0 为好，1–127 为坏，125 为跳过）。
- `git revert <commit>` 新建一个反向提交，默认说明为 `Revert "<原标题>"` + `This reverts commit <hash>.`；适合已推送的公共分支。再 revert 这个撤销提交即可恢复。
- `git cherry-pick <commit>` 把指定提交的改动作为新提交应用到当前分支（哈希不同）；冲突时解决后 `git add` + `git cherry-pick --continue`；`-x` 在说明末尾追加 `(cherry picked from commit <hash>)`。
