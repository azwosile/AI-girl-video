## 5. 事实核对（docs.github.com，2026-10）

- Git 推送超过 50 MiB 的文件会警告；GitHub 拒收超过 100 MiB 的文件（报错 GH001 Large files detected）；浏览器上传上限 25 MiB。仓库建议小于 1 GB，强烈建议小于 5 GB；发布大的二进制文件用 Release。
- 文件只在最近一次未推送的提交里：`git rm --cached FILE` → `git commit --amend`，再推送；在新提交里删除没有用。更早的提交里有，需要改写历史（git filter-repo，或满足条件时用交互式变基）。
- Git LFS：仓库里只存指针文件（`version https://git-lfs.github.com/spec/v1`、`oid sha256:…`、`size …`）；`git lfs track` 写进 `.gitattributes`，这个文件要提交；免费账户单文件上限 2 GB，免费额度 10 GiB 存储 + 每月 10 GiB 流量。**Git LFS 不能用于 GitHub Pages 网站和模板仓库。**`git lfs migrate import` 会改写历史，之后要强制推送。
- `.gitattributes` 里 `* text=auto` 让 Git 自动处理文本文件换行（仓库里统一为 LF）；`eol=lf` 固定检出换行；`binary` 表示不做换行转换和 diff；加规则后用 `git add --renormalize .` 重新整理已跟踪文件。
- 误推敏感数据：第一步是撤销 / 轮换密钥，很多情况下这就足够；要清理历史用 `git-filter-repo --sensitive-data-removal`（`--invert-paths --path PATH` 删除文件，或 `--replace-text` 替换，默认替换成 `***REMOVED***`），然后 `git push --force --mirror origin`；协作者要重新克隆或变基，不能合并；PR 里的缓存视图和引用需联系 GitHub Support；用户级推送保护默认开启，会阻止向公开仓库推送密钥。
- 实战里只想去掉密钥、保留 config.js，所以用 `--replace-text`；`--invert-paths --path config.js` 会把文件从所有提交（包括最新的）里删掉。
