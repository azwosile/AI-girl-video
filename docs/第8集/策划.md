## 4. 配音要点

- 命令里的英文照读，关键处加中文提示：rebase 前面带“变基”；`--continue` / `--abort` / `--force-with-lease` 读英文；`HEAD~4` → “HEAD 波浪线 4”；`HEAD@{5}` → “HEAD at 5”；`origin/main` → “origin 斜杠 main”。
- “变基”容易被读成“电机 / 电击”（d 声母）。同一句的音素是固定的，差别来自生成时的随机性：可疑句用多个种子各出一版，挑 b 声母清楚的（记在 `tts_gen.py` 的 `SEED_OVERRIDE`）。标题句 G01_03 和 K01 试了 7 个种子都不行，改了台词：标题句念“第八集，整理提交历史！”，K01 念“历史整理坏了也不怕”。
- 审核用 Paraformer（`asr8.py`），英文词它认不准，以中文部分和时长判断。
- Gemini 台词开头带“喵？”；豆包用自己的 GPT-SoVITS 模型（`tts_doubao.py`，参考音频 r19）。
- 每次跑完都逐句做 ASR 审核。

## 5. 事实核对（git-scm.com / docs.github.com，2026-10）

- `git rebase <base>` 把当前分支上 base 之后的提交逐个重放到 base 末端，生成新的提交（哈希改变）。
- `git pull --rebase` 用变基代替合并；`git config --global pull.rebase true` 设为默认。工作区有未提交改动时变基会拒绝开始，可以先提交或 `git stash`（也有 `--autostash`）。
- 冲突时变基停下，解决后 `git add` + `git rebase --continue`；`git rebase --abort` 回到变基开始前。
- `git rebase -i` 的待办清单按从旧到新排列（和 `git log` 默认顺序相反）；`squash` 把提交并入上一个并合并说明，`fixup` 并入但丢弃本条说明，`reword` 改说明，`drop` 删除，调整行序即调整提交顺序。
- 推送过的提交变基后普通推送会被拒（non-fast-forward）；`--force-with-lease` 在远端有自己没见过的新提交时拒绝覆盖。
- 分支保护规则 / 规则集默认禁止强制推送到受保护分支。
- `git reflog` 记录 HEAD 的移动，可用 `git reset --hard HEAD@{n}` 回到之前的位置。
- GitHub PR 合并按钮提供 Create a merge commit / Squash and merge / Rebase and merge；Squash and merge 后原来的提交仍能在 PR 页面查看。
